# Пункт — интерактивная концепция

Рабочий главный экран по утверждённой композиции: Vue 3, TypeScript, Vite. Брендовые цвета `#FFC107` / `#171717`. Onest используется в интерфейсе, Roboto Condensed — в заголовке HERO.

## Запуск

Нужен Node.js 22.12+ (проверено на 24.22.1).

```sh
cd /workspace/PUNKT
npm ci --cache /tmp/punkt-npm-cache
npm run dev -- --port 5173
```

Сборка — `npm run build`. Проверка production-сборки — `npm run preview -- --port 4173`.

## UI-кит

Откройте `/?ui-kit#ui-kit`. Здесь собраны цвета и типографика утверждённого мобильного интерфейса, интерактивные поля калькулятора, фильтры, карточки с характеристиками, кнопки и состояния формы.

Для следующих страниц используйте переменные из `src/style.css` и компоненты `SelectField`, `DateRange`, `DeliveryAddress` и `BaseModal` из `src/components`. `FleetCard` с параметром `detailed` показывает фото, класс, характеристики и цену за сутки, как в мобильном автопарке. Примеры полей UI-кита используют собственные значения.

## Что работает

- Прозрачная навигация поверх сцены, светлая адаптация логотипа с жёлтым акцентом и три группы услуг в меню и мобильном аккордеоне.
- Отдельный полупрозрачный виджет доставки с автомобилем. В справках доставки, пробега и «Защиты+» показано по одному фотокадру.
- HERO на всю высоту окна desktop; панель закреплена снизу и раскрывается вверх; быстрый выбор закрыт по умолчанию. На мобильных предусмотрена прокрутка содержимого.
- Класс автомобиля, даты с проверкой диапазона, место получения, лимит пробега со справкой, Защита+, доставка со справкой и контекст арендатора. Доставка синхронизирована с местом получения.
- В поле места получения доступны офис, аэропорты и ручной ввод адреса. Подсказки улиц и домов используют локальный демонстрационный набор. Возможность доставки и корректность адреса подтверждаются перед оформлением.
- На десктопе быстрый выбор открывает карусель с фильтрами. На мобильных все машины сразу показаны под формой в вертикальном списке.
- Страница «Цены» (`/?page=prices`) открывается из меню и формы подбора. На ней есть цена за срок и за сутки, параметры поездки, фильтр по классу и сортировка.
- У машины и формы заявки есть свои страницы (`/?page=car&car=1` и `/?page=request&car=1`). Карточка показывает галерею, характеристики, условия выдачи и расчёт при смене пробега. При переходах внутри сайта параметры аренды и фильтры сохраняются, а прямые ссылки открываются с параметрами по умолчанию.
- Валидация имени, телефона и согласия. Корректный демонстрационный результат без фиктивной отправки.
- Модальные окна акции, услуг, условий, новостей и входа в кабинет; закрытие Escape, удержание и возврат фокуса.
- Hover, focus, pressed, disabled, error; поддержка reduced motion.

## Границы текущего этапа

Это frontend-прототип, не опубликованный сервис. Нет backend, реальной отправки, SMS, авторизации, хранения персональных данных, реального наличия автомобилей и оплаты. Кнопка кабинета показывает предварительный состав и статус, не выполняет вход. Содержание отдельных разделов показано в модальных окнах: полноценные страницы вне текущего этапа.

Семь автомобилей и тарифы — демонстрационные. Базовые примеры Solaris/Rio/BMW/Camry взяты из нового ТЗ; кроссоверы, Volkswagen Polo, надбавки 700/1500 ₽ за пробег и 490 ₽ за «Защита+» нужны только для демонстрации расчёта. Они не являются утверждёнными тарифами. Залог и доставка не входят в пример итога; это явно указано. Количество суток считается по календарным датам; часы и бизнес-правила расчёта нужно уточнить до интеграции.

В виджете акции «10 января» — рабочая дата макета. Срок, год и территория требуют согласования перед публикацией. Бесплатная доставка не включается автоматически. Документы не загружаются через сайт. Действующий юридический PDF, политика, реквизиты, ссылки на мессенджеры и данные реального автопарка ожидают подключения.

На десктопе первый экран показывает зацикленное видео доставки без звука с кнопкой паузы. При ограничении движения видео запускается вручную. На мобильных показывается только стоп-кадр передачи ключей. Галерея Solaris и её расширенные характеристики используют пример из клиентского макета. Для остальных моделей используются ракурсы на основе иллюстраций. Для запуска нужны реальные фотографии и подтверждённые характеристики автопарка.

## Проверки

```sh
npm run build
npm test
```

Playwright использует `/usr/bin/chromium`. При другом расположении: `CHROMIUM_PATH=/путь/к/chromium npm test`. Проверяются календарь, фильтры, расчёт, валидация, фокус модальных окон, галерея, карусель, отсутствие горизонтального переполнения, видимость всех опций и неизменная высота HERO на 320 / 430 / 768 / 1024 / 1440 / 1536 / 2048 px.
